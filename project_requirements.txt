Project to be done:
Challenge: Lead nurturing workflow with AI agent 

Sales follow-up personalization using lead context from CRM

Overview
Property Sales associates need an efficient way to send personalized follow-ups to leads stored in the CRM. This feature enables them to trigger automated, context-aware emails or WhatsApp messages, leveraging past enquiry data from the CRM for personalization.
Goal for the AI agent solution:

Revive past customer leads from the existing CRM/database for the ongoing sales campaign and convert them into property visits for the target real estate project of this campaign. 

What’s different from existing automation solutions offered by CRMs?

AI agent capability to hyper-personalise the messaging for each customer lead based on the past data available in the CRM (mock sheet shared in this case). Use any information available about their qualitative information (family size etc, unit type preferences - 1 bed, 2 bed, etc, budget, location etc.) to frame this personalized email message that takes into account the features of the project being marketed in this campaign. 
Key Capabilities of the agentic solution
    • Enable sales associates to shortlist specific leads based on a given criteria from the CRM & send out hyper-personalized outreach messages as scale with relevant project details by creating a dedicated lead nurturing campaign. 
    • Hyper-Personalization of the nurturing outreach message is based on lead history and sales preferences and last qualitative context captured about the customer profile, demographics, purchase motive, intent, financing options, etc.
    • Automation of email message dispatch to the shortlisted CRM leads without manual intervention.
    • Any customer responses to these nurturing outreach messages are then responded to by the AI agent along with building urgency to consider a purchase and nudge the customer for scheduling a viewing to the property. There could be multiple conversation turns in this process between the customer & the AI sales agent. 
    • If the customer agrees for a call with a sales advisor or to schedule a property visit appointment, then the AI agents sets up the call/visit and notifies the designated sales associate’s email ID. 
    • All information is updated in a central lead nurturing campaign dashboard, which would list campaign wise data points around number of leads shortlisted, number of messages sent, no. of responses received and number of visits/calls set up (goal accomplished). 
User Flow
    1. Sales associate selects leads
        ◦ Filters leads based on criteria such as last conversation date, project name enquired previously, budget, unit type, and lead status.
    2. Sales associate personalizes the message
        ◦ Selects the project to pitch. (note this is the target project the client is selling. Not to be confused with the project name the customer/lead might have enquired earlier). 
        ◦ Choose the message channel (limited to email for the purpose of this challenge)
        ◦ Inputs any special ongoing property sales offer to be highlighted in a text field.
    3. System sends personalized messages
        ◦ Messages are automatically generated based on past structured and qualitative data available about the lead in the CRM and dispatched to the selected leads.
        ◦ The message could be sent over email for the purpose of this challenge. 

Note: This is an important part of the agent. You will have to construct a prompt template to match the customer information including the ‘last conversation summary’ available in the CRM sheet with the project features of the project name targeted in the campaign. 
    4. Customer responds
        ◦ Some customers might respond to this nurturing outreach message over email or whatsapp asking for further information or expressing interest for a call or property viewing (goal). 
    5. System (AI agent) responds back to customer
        ◦ The AI agent understands the intent of customer response. If the intent is clear that customer has selected a goal outcome already (property viewing/sales call), the agent triggers the notification to the sales team. If the intent involves asking further questions about the property or other properties, the AI agent retrieves relevant information from the database and responds to the customer with the information, while also nudging them towards the goal.

Technical requirements:
I. Architecture and Communication
The core requirement is to develop an intelligent agent orchestrated using LangGraph and served by a Python web application.
    • Application Framework (Choice): The agent service must be hosted within a standard Django Ninja (preferred) OR a Django application (using Django REST Framework). The candidate must clearly state the chosen framework.
    • Agent Orchestration: The agent's logic and state management must be handled by LangGraph.
    • Database Flexibility: The relational database can be either PostgreSQL or SQLite. The candidate must clearly document the chosen option.
    • LLM Choice and Follow-up:
        ◦ The developer has full flexibility to choose any LLM model or architecture to power the agent.
        ◦ The developer should expect a follow-up interview to dive deeper into the technical decisions made regarding the LangGraph design and the specific LLM model/architecture selected.
II. API Design Standards
The Agent API must strictly follow RESTful best practices and align with industry standards for security and performance.
    • Resource Naming: Use nouns (plural) for resource collections.
    • HTTP Methods: Correctly map HTTP methods to actions. A single POST endpoint is expected for submitting a new user query to the agent.
    • Status Codes: Use appropriate HTTP Status Codes for responses (e.g., 200 OK, 201 Created, 400 Bad Request, 401 Unauthorized, 404 Not Found, 500 Internal Server Error).
    • Authentication (Mandatory): All communication with API endpoints must be secured using JSON Web Token (JWT) authentication, returning a 401 Unauthorized response if the token is missing or invalid.

III. Agent Capabilities
The LangGraph agent must function as a router, deciding whether to execute a Text-to-SQL task or a Document RAG task based on the user's query.
A. Text-to-SQL (T2SQL) Requirement
The agent must interpret natural language queries into SQL using Vanna.
    • T2SQL Library: The Vanna framework must be used to provide the Text-to-SQL capability.
    • Vector Store: ChromaDB must be used as the vector store to host Vanna's training data (DDL, documentation, SQL examples).
    • Agent Capability: The agent must interpret a natural language query, utilize a Vanna tool to generate and execute the appropriate SQL query against the relational database, and return a meaningful, natural language response based on the result.
    • Data Handling: The chosen relational database should contain a sample schema and data sufficient to demonstrate the T2SQL capability.
B. Document RAG Requirement (Brochures)
The agent must be able to retrieve information directly from provided unstructured documents (brochures).
    • Vector Store: The processed brochure data must be stored and searched using ChromaDB.
    • Agent Capability: The LangGraph agent must utilize a Document RAG tool to perform a semantic search against the brochure vectors in ChromaDB, retrieve the most relevant text chunks, and use the LLM to synthesize an accurate, natural language answer.
IV. Development Requirements
    • Codebase: A complete, working codebase containing the application framework and the full LangGraph agent.
    • Dependencies: A clear and reproducible list of project dependencies (e.g., requirements.txt).
    • Document Ingestion API (Mandatory): A dedicated upload endpoint must be created to handle the ingestion of brochure documents. This endpoint will trigger the following pipeline:
        1. File Upload: Accepts the brochure file(s).
        2. Chunking/Splitting: Implements a strategy (e.g., recursive text splitting) to break the brochures into manageable chunks.
        3. Embedding: Uses an appropriate Embedding Model (must be documented) to convert the text chunks into vectors.
        4. Storage: Stores these vectors, the original chunks, and relevant metadata in ChromaDB.
    • Documentation: Clear instructions on environment setup, configuration of both databases, and usage of the Document Ingestion API.
V. Testing and Evaluation
A robust testing and evaluation suite is mandatory.
    • Testing Framework (Mandatory): All tests must be written using Pytest.
    • Unit/Integration Testing: Thorough tests for the API workflow, Document Upload/Ingestion flow, T2SQL flow, and the Document RAG retrieval and generation.
    • Agent Evaluation (DeepEval):
        ◦ The agent's performance must be evaluated using the DeepEval framework.
    • Evaluation Results: The DeepEval agent score results must be captured and shared in a separate, dedicated file (e.g., agent_evaluation_scores.json).
    • Reproducibility: The evaluation process must be easily reproducible via a single script or command (e.g., pytest run_eval.py).
VI. Deployment and Submission
The final deliverable consists of two parts.
    • Hosting Platform: The entire application must be deployed to some cloud environment that is public facing. You can use Render (https://render.com/) as a free alternative.
    • Deployment Status: The deployed application must be live and fully functional upon submission.
    • Submission Artifacts (Mandatory):
        1. The live link to the hosted application.
        2. A ZIP file containing the complete source code for the challenge.
